### 1-2. 출제 기본값: 시작 = 지금, 마감 = 7일 뒤 (`/app/tests/new`)

- 3 조건에 **시작**(지금 / 예약 → datetime) · **마감**(**1주 뒤** 기본 · 오늘 · 이번 주 · 직접 · 없음) 블록. 1주 뒤 = 시작 시각 + 7일, 시각 그대로 (예약 시작을 바꾸면 마감도 따라감).
- 마감 ≤ 시작이면 인라인 오류 + 동작 바 문구 + 출제/초안 버튼 비활성. 서버 액션(`createExamAction`·`assignStudentsAction`)도 같은 조건을 거부.
- 시작 "지금"은 서버 시각으로 저장(`startAt = new Date()`), 학생 앱은 즉시 응시 가능. 예약이면 학생 앱 카드에 "9. 24. AM 09:00 부터 응시할 수 있어요", 대기 줄에는 `WAIT`, start API 는 409.
- 미리보기 요약·동작 바에 `시작 지금 · 마감 09/30 15:32` 표시.
- **선생님 계정의 반 칩 인원 = 담당 학생 수** (이전엔 반 전체 인원으로 보여 출제하면 0명 배정되는 경우가 있었음). 담당 학생이 없는 반은 0·비활성, 안내 문구도 역할별.
- 시험 상세: 출제 상태 카드에 `시작 … · 마감 …` 줄(예약이면 "예약", 일부만 예약이면 "학생마다 다름"). 마감 카드가 전원 완료 뒤 "마감 없음"으로 보이던 문제 → "현재 마감 … · 모두 완료".
- 대상 추가 패널: 시작(지금/예약) 세그먼트 + 마감(기존 대상과 같게, 없으면 7일 뒤) 세로 배치 — 340px 패널에 datetime 두 개를 나란히 두어 값이 잘리던 문제 해결. 반 목록은 **더할 학생이 있는 반만 인원과 함께**, 없으면 비활성. 담당 아닌 반을 고르면 "학생을 선택하세요" 대신 "이 반에는 내 담당 학생이 없어요…".
- 시험 목록: 머리글 kicker(`TESTS · 시험`) 다른 페이지와 통일, **마감 열** 추가(지난 마감은 강조색 "지남", 예약 시작은 "· 시작 예약").

## 3. 출제 흐름 QA (`npm run e2e:compose`, 41/41)

1. **업로드**: `READY` → `.hwp` 고르면 경고·버튼 비활성 → × 취소 → 이어 붙이기 목록(단어 수·DAY, select 없음) → `sample.docx` → `1 FILE` → 업로드 → import → 단어장 자동 열림. 같은 파일 재업로드 → 기존 단어장 안내.
2. **출제(선생님1)**: B반 칩 = 0·비활성(담당 아님). 시작 프리셋 = 지금, 마감 기본 = +7일 같은 시각, 동작 바에 `시작 지금 · 마감 mm/dd`. 마감<시작 → 오류·비활성 → 1주 뒤로 복귀. 출제 → `published=1&assigned=5`. 상세에 `시작 … · 마감 …`. DB: `startAt` ≈ 서버 지금(±5분), `dueAt` = `startAt`+7d, 5명 마감 동일.
3. **상세 3단계**: 1 단어 목록(발행 칩·미리보기) → 2 선생님은 더할 학생 0·반 select 비활성 → **학원장**이 B반 추가(시작 지금, 마감은 기존과 같게 자동) → 10명 → 3 마감 카드 "현재 마감", 기간 줄 하나.
4. **학생(휴대폰)**: 홈에 바로 노출, start API 200, 러너 4지선다.
5. **예약 시작**(내일 09:00): 1주 뒤 마감이 따라 이동(10/01 09:00), 상세에 "예약", 학생 start API 409, 홈에 `WAIT`/"부터 응시할 수 있어요".
6. **초안만 저장** → 상세 1단계(발행 배너 없음) → 발행 → 자동으로 2단계 → 마감 기본 7일 뒤 → A반 5명.
7. 대상 추가 패널도 마감<시작 차단 → 고치면 다시 활성.
8. 시험 목록 마감 열.
