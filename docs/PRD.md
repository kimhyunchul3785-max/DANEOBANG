# 단어방 — PRD (학원용 단어 테스트 관리 SaaS)

문서 버전: 3.0 (1차 MVP 구현 기준) · 기준일: 2026-09-22
상태: 1차 구현 완료 항목과 후속 범위를 구분해 기술한다. 이전 문서(2.0, 단일 선생님 "유진T 단어방" 전제)를 대체한다.

## 0. 결정 사항

- **대상은 특정 선생님이 아니라 전국의 학원이다.** 학원이 가입(개설)해 하나의 테넌트가 되고, 학원 안에 선생님 계정을 두며, 선생님이 담당 학생을 관리한다.
- 계정 구조: `User(실제 사람)` — `AcademyMember(어느 학원에서 어떤 역할)` — `Academy(테넌트)`. 학원 자체는 로그인 계정이 아니다. 한 사람이 여러 학원에 속할 수 있다.
- 역할: `PLATFORM_ADMIN`(서비스 운영), `OWNER`(학원장), `TEACHER`(선생님), `STUDENT`(학생 명단에 연결된 계정).
- 로그인: Google OAuth, Kakao Login, 이메일·비밀번호(개발/파일럿용, 운영에서 끌 수 있음). 공급사 토큰을 세션으로 쓰지 않고 서버가 사용자를 확인한 뒤 단어방 자체 세션(웹: HttpOnly 쿠키, 모바일: Bearer 토큰)을 발급한다.
- 웹앱(Next.js)이 1차이며, 모바일(Android/iOS)은 같은 REST API(`/api/v1`)를 사용하는 React Native/Expo 앱으로 후속 구현한다. 백엔드를 다시 만들지 않는다.
- 1차 MVP 데이터베이스는 SQLite(Prisma)이며 PostgreSQL 전환은 provider 변경만으로 가능하도록 enum·특수 타입을 쓰지 않았다.
- HWPX·DOCX·텍스트 PDF 단어장 등록, 종이 시험지(QR·마킹) 사진 채점을 1차 범위에 포함했다. `.hwp`(바이너리)는 지원하지 않는다.

## 1. 제품 정의

선생님이 검수한 단어 데이터로 DAY별 무작위 사지선다 시험을 만들고, 온라인 응시와 종이 답안 사진 채점을 같은 학생 기록에 모아 성적·재시험·오답노트까지 관리하는 **학원 단위 멀티테넌트 웹앱(+모바일 API)**.

해결하는 문제: 시험지 편집·정답 관리·종이 성적 재입력·재시험 대상 관리의 반복 노동. 제품이 보장하지 않는 것: 모든 문서 양식의 무검수 완벽 추출, 사진 판독만으로의 부정행위 방지, 성적 향상.

## 2. 사용자와 소유 단위

| 역할 | 할 수 있는 일 | 제한 |
|---|---|---|
| 플랫폼 운영자 | 학원 이용 정지/복구, 요금제 라벨, 사용자 정지, ADMIN 부여, job 재실행, 감사 로그 | 학생 개별 내용의 상시 열람 기능 없음 |
| 학원장(OWNER) | 학원 정보, 선생님 초대(7일·1회용 링크), 담당 선생님 지정, 전체 학생·단어장·시험·성적, 사용량 확인 | 다른 학원 접근 불가 |
| 선생님(TEACHER) | **담당 학생**의 명단·초대·연결 승인, 단어장·시험·채점·재시험·오답노트 | 학원 설정·초대·담당 지정 불가, 담당 아닌 학생 접근 불가 |
| 학생 | 본인 배정 시험 응시, 점수·정답(공개 정책에 따라), 오답노트 | 정답 키·다른 학생·단어장 원본 접근 불가 |

학생 명단(`Student`)과 로그인 계정(`User`)은 분리된다. 선생님은 계정 없는 학생을 등록해 종이 시험 성적을 쌓을 수 있고, 학생이 가입한 뒤 학생별 일회용 초대 링크 → 연결 요청 → 선생님 승인으로 기존 기록에 연결한다. 이름이 같다는 이유로 자동 연결하지 않는다.

## 4. 핵심 흐름

1. **선생님 첫 사용**: 가입 → 학원 개설(OWNER) → 반·학생 등록 → HWPX/DOCX/PDF 업로드 → 추출 검수(DAY 지정·행 수정·제외) → 단어장 저장 → 시험 생성(DAY 복수 선택) → 문항 초안 검토·발행 → 학생 배정 → 온라인 응시 또는 학생별 PDF 발급.
2. **학생 온라인**: 초대 링크 → 가입/로그인 → 연결 요청 → 승인 → 내 시험 → 응시(자동 저장, 새로고침 복원) → 제출 → 서버 채점 → 공개 정책에 따른 결과·오답 복습.
3. **종이 시험**: 학생별 PDF(QR·기준점·문항 일체형 마킹 원) → 마킹 → 선생님이 촬영 업로드 → QR 식별·원근 보정·마킹 판독 → 선생님 검수(불확실·복수 마킹은 반드시 지정) → 페이지 확정 → 모든 페이지 확정 시 공통 채점.
4. **재시험**: 통과 미달 확정 시 task 1회 생성 → 기한 지정 → "오답만" 또는 "같은 범위" 재시험 초안 생성 → 검토·발행 시 자동 배정 → 통과하면 task 완료(최초 실패 기록은 보존).

## 6. 비기능 요구사항

- **테넌트 격리는 서버가 보장한다.** 모든 조회에 `academyId`와 담당 범위(`studentScope`)를 조건으로 넣고, 파일·PDF·사진 URL은 권한 검사 후에만 응답한다. 다른 학원 리소스는 존재 여부를 노출하지 않는다(404). E2E로 교차 접근 차단을 검증했다.
- 학생 DTO에는 `itemId`, 영어, 보기 텍스트·순서만 포함한다. 정답·seed·출처를 보내지 않는다(E2E 검증).
- 업로드는 확장자가 아니라 매직 바이트로 형식을 판정한다. 문서 50MB, 이미지 20MB, ZIP 해제 200MB, PDF 200페이지 제한.
- 문서·PDF·사진 처리는 영속 job(`Job` 테이블)으로 실행되며 서버 재시작 시 대기 job을 재개한다. 실패는 3회 재시도 후 실패로 기록되고 운영자가 재실행할 수 있다.
- 시간은 UTC 저장, 표시·주간 집계는 Asia/Seoul.
- 개인정보: 학생 이름·반·(선택) 학교·학년만 수집. 휴대폰·생년월일 미수집. 사진·원본 파일 보관 기간 정책은 운영 승인 후 삭제 job으로 구현(후속).

## 7. 후속 범위 (1차 미포함)

네이티브 앱 자체(React Native/Expo 프로젝트), 푸시 발송, 이메일 발송(초대는 링크 복사), 스캔 PDF OCR, HEIC 업로드, 학생 직접 사진 제출, 검수 없는 자동 확정, 학생별 개별 문제 버전 자동 배정, 결제·구독, 학부모 포털, 문자/알림톡, 파일 보관기간 자동 삭제, MFA, CAPTCHA, PostgreSQL/S3/Redis 운영 인프라 전환.
